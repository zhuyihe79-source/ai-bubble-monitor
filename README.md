# AI 泡沫监测

每天采集免费公开数据，判断 AI 这一轮处在哪个阶段（价格破没破、需求破没破），算出 0–100 的“AI 泡沫温度”，加上 AI 分析师的新闻评级，发布成静态看板。

## 运行

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
export SEC_USER_AGENT="你的名字 you@example.com"   # SEC 要求带联系方式
.venv/bin/bubblemon-fetch                           # 采集；可加 --only id1 id2
.venv/bin/streamlit run app/dashboard.py
.venv/bin/bubblemon-report                          # 生成独立 HTML 看板 data/dashboard.html
.venv/bin/pytest
```

## 结构

- `config/indicators.yaml`：指标注册表。新增指标只改这里（加 fetcher 时再改代码）。
- `src/bubblemon/fetchers/`：每个数据源一个采集器，统一返回 `pd.Series`（日期 → 值）。
- `src/bubblemon/db.py`：DuckDB，表 `observations(date, indicator_id, value, source, fetched_at)` 和 `fetch_log`。
- `src/bubblemon/scoring.py`：周频对齐 → 15 年滚动分位 → 维度均值 → AI 泡沫温度和市场宽松度。
- `src/bubblemon/triggers.py`：破裂信号。`src/bubblemon/phase.py`：信号分层、阶段判断、历史对照。
- `src/bubblemon/alerts.py`：AI 泡沫温度越线、单指标极端值。
- `data/manual/*.csv`：没有免费接口的指标可以手工录入（`date,value`，`source: manual`），目前没有使用。

## 方法

看板回答三个问题，分开看：

| 问题 | 看什么 | 更新频率 |
|---|---|---|
| 现在是哪种局面？ | **阶段**：价格破没破 × 需求破没破，四选一 | 价格每天，需求每季 |
| 吹得多大？ | **AI 泡沫温度**（0–100）= 价格与估值、投资强度两项的平均 | 每天 / 每季 |
| 最近的消息偏好还是偏坏？ | **分析师风险评级**（1–5），只基于新闻 | 每天 |

另有**市场宽松度**（信用利差、VIX、利率）作为大环境参考，不是 AI 专属，不进温度。

### 阶段

11 个破裂信号分四层（`config/indicators.yaml` 的 `layer`）：

- **需求**：云厂商单季 capex 同比、NVDA 单季收入环比、NVDA 单季收入同比。来自 SEC 季报。
- **价格**：NVDA 距 52 周高点回撤、半导体相对标普 500 的 3 个月变化。
- **融资**：云厂商 capex / 经营现金流、有息负债同比、高收益债利差 3 个月变化。
- **情绪与利率**：VIX、10 年期实际利率 3 个月变化、Google 搜索 “AI bubble” + “AI crash”。

每层取层内最差的状态。阶段只由需求层和价格层有没有“触发”决定（`src/bubblemon/phase.py`）：

| | 需求没破 | 需求已破 |
|---|---|---|
| **价格没破** | 扩张 | 需求数据偏弱，价格未破 |
| **价格已破** | 价格回调，需求未证实转弱 | 破裂确认 |

融资、情绪与利率两层不改变阶段，它们说明回调来了会有多疼。需求层的“警戒”也不改变阶段：警戒线是按这一轮 60% 以上的增速定的，放在 2023 年以前属于常态。

看板上的“历史对照”每次构建时用当时已公布的数据重算两张表：四个阶段各出现在什么时候、之后半年 NVDA 怎么走；NVDA 每次跌破 −35% 之后收入有没有跟着掉、又跌了多少。

### AI 泡沫温度

1. 每个指标转成周频（周五，最后一点是最新交易日），前值填充；超过 `max_stale_days` 视为缺失。
2. 季度财报数据按 `publication_lag_days`（35 天）后移，避免历史分数用到当时还没公布的数据。
3. 取过去最多 15 年（至少 3 年）的滚动分位；`direction: low` 的指标取 `1 - 分位`。
4. 维度内等权平均，两个维度再平均，乘以 100。只发布 `ai_start`（2023-01-01）之后的读数。

| 维度 | 指标 |
|---|---|
| 价格与估值 | NVDA 市销率（市值 ÷ 近四季收入）；SMH/SPY 比自身三年均值高出多少；SPY/RSP 比自身三年均值高出多少 |
| 投资强度 | 五大云厂商 capex 同比（滚动四季）；capex ÷ 经营现金流 |

市销率的股数取自申报封面，按之后的拆股比例换算；收入在季末后 35 天才计入。

### 2026-11-22 的方法调整，以及为什么

调整前用真实数据做了回测，发现四个问题：

1. **温度饱和，对价格没有反应。** 旧版“估值”维度用 SMH/SPY、SPY/RSP 的比值本身取分位。这两个比值十几年一路上行，2023 年以来分别有 99% 和 90% 的周分位在 0.9 以上。2026 年 11 月 NVDA 从高点跌掉 48%，温度只从 82 降到 80。而且这个维度里没有任何真正的估值指标。现在改成偏离三年均值，并加入市销率；同一天的新读数是 68（价格与估值 37，投资强度 100），2023 年以来的范围是 49–95。
2. **“云厂商单季 capex 环比”有季节性误报。** 云厂商一季度 capex 习惯性回落，2017、2019、2023 年的一季度都因此触发。已删除，改用单季同比：2016 年以来转负只有 2019 年和 2023 年两段，都是真实的投资消化期。新增 NVDA 单季收入环比：2016 年以来跌超 10% 有三次，2019 年初（−31%）和 2022 年下半年（−19%）是真实的下行，2017 年初（−11%）是季节性回落。
3. **数信号个数没有意义。** “3 项触发、4 项警戒”把滞后一个季度的财报和每天变的股价混在一起数；价格类信号总是一起亮，而且历史上 VIX 冲高、NVDA 深度回撤之后，半导体三个月回报反而高于平均。现在分层，并在信号表里给出每个信号的历史频率（2016 年以来有多大比例的周处于警戒或触发）。
4. **没有结论。** 温度、宽松度、信号个数、评级四个数并排，读者得不出“现在算什么情况”。现在用阶段回答。

阶段规则也回测过。第一版把需求层“警戒”也算进阶段，结果 2016 年以来有 48% 的周被判成“需求转弱”或“破裂确认”，其中包括 2023 年全年，明显不对，所以改成只认“触发”。现行规则逐周回算（2016-01 至 2026-11，NVDA 之后半年的表现）：

| 阶段 | 占比 | 出现在 | 之后半年涨跌（中位数） | 半年内最深跌到（中位数） |
|---|---|---|---|---|
| 扩张 | 69% | 其余时间 | +23% | −8% |
| 价格回调，需求未证实转弱 | 7% | 2018-11 至 2019-03；2022-04 至 2022-09；2025-04；2026-11 起 | +3% | −26% |
| 需求数据偏弱，价格未破 | 16% | 2017 年夏；2019-10 至 2020-02；2023-01 至 2024-02 | +64% | −5% |
| 破裂确认 | 8% | 2019-03 至 2019-09；2022-09 至 2023-01 | +60% | −8% |

读法：阶段是对现状的分类，不是预测。最难受的是“价格回调”这一格，因为它是岔路口：2010 年以来 NVDA 跌破 −35% 共 6 次，4 次随后收入环比跌超 10%，从跌破那天算又跌了 27%–47%；2 次收入没掉（2020-03、2025-04），跌破那几天就是低点。而财报比股价慢：那 4 次等财报证实时，股价已经比高点低了 40%–59%。所以“破裂确认”出现时大部分跌幅已经发生，它不是卖出信号。每个阶段只来自两三段行情，这些数字只说明方向。

## 破裂信号与每周解读

- `config/indicators.yaml` 的 `triggers:` 定义 11 个信号，每个有所属的层、警戒线、触发线和“为什么重要”。改阈值只改这里。
- 信号状态可以按任意日期回算（`triggers.evaluate(series, cfg, asof)`；整段历史用 `triggers.history`），财报数据按季末后 35 天才算可见，所以历史状态不会用到当时还没公布的数据。
- 每周解读（`commentary.weekly_note`）自动生成：阶段和依据、信号状态变化、AI 温度变化拆到具体指标、市场周表现、最新财报要点、需要盯住的信号。看板保留最近 8 周。
- 价格、单季 capex、NVDA 收入、云厂商有息负债等序列标了 `score: false`，只用于信号和解读，不进入任何分数。
- 云厂商有息负债 = 长期债务（非流动）+ 一年内到期部分，不含租赁负债。合并序列从 2023 年底开始，因为 Meta 更早的季度申报有缺口。

## 新闻与分析师周报

新闻不是爬虫抓的，由定时任务里的 AI 分析师按 `analyst/GUIDE.md` 阅读、核实、打分后写入仓库。

- `news/YYYY-MM-DD.json`：当天收录的新闻，四个主题（存储、英伟达、融资、需求），每条有重要性 1–5、风险方向、可选的关联破裂信号。
- `notes/YYYY-MM-DD.md`：分析师周报，每周一写，出现重要性 5 的新闻时加写。
- `bubblemon-news-check`：校验新闻文件格式，提交前必须通过。
- 看板显示最新周报、近 7 天要闻和各主题 8 周新闻热度（重要性 ≥ 3 的条数和风险净方向）。新闻不进入泡沫温度的计算。
- **分析师风险评级（1–5）**：近 7 天新闻按重要性加权的净方向，按固定规则换算成规则值；分析师每次运行可在规则值上下各调一级并写明理由（新闻文件的 `assessment`）。显示在泡沫温度旁边，规则见 `analyst/GUIDE.md`。
- **新闻预警**：关联到某个破裂信号、重要性 ≥ 4、风险上升的新闻，会在信号表里标出，作为财报数据到来前的提前提示。

## 已知局限

- **需求层滞后。** 它用的是已提交 SEC 的季报，季末后约 35 天才更新，而过去每次破裂都是股价先跌。需求层“正常”不等于安全；财报之前只能靠新闻预警和分析师评级。
- **样本很少。** NVDA 深度回撤 2010 年以来只有 6 段（前两段还是 PC 显卡时代），云厂商有息负债只有 2 年数据，高收益债利差 FRED 只给近 3 年。历史对照说明方向，不是概率。
- **阈值是人定的。** 信号表里的历史频率用来校准，但没有做过优化；需求层警戒线只适用于这一轮的高增速。
- **温度只和自身历史比。** 80 以上说明这些指标处在过去 15 年的高位，不等于和 2000 年互联网泡沫一样极端，也不是择时工具。季度财报公布那一周温度会跳一下，这是真实数据更新。
- **市销率的股数是近似值**：取申报封面的流通股数，两次申报之间不变。
- **分析师评级偏向坏消息。** 评级是近 7 天新闻的加权净方向，而“会改变判断的新闻”天然以风险为主：头一周收录的 63 条里风险上升 39 条、下降 5 条，规则值连续 7 天都是 5。手册已要求每个主题专门搜反面证据，看板也列出上升和下降各几条，但这个偏差不会消失。
- **Google Trends 是相对值**，且会限流；失败只记录在 `fetch_log`，不会中断其他指标。
- **没有覆盖**：未上市公司（OpenAI、Anthropic 等）的财务、表外和私募信贷融资、GPU 租金、企业端 AI 实际付费、融资余额。这些只能靠新闻。
- 历史太短的指标不计分（高收益债利差、搜索热度），只用于破裂信号。

## 上线（GitHub Pages）

1. 把项目推到 GitHub 仓库，默认分支叫 `main`。
2. 仓库 Settings → Pages → Source 选 **GitHub Actions**。
3. （可选）Settings → Secrets and variables → Actions，新建 secret `SEC_USER_AGENT`，值如 `你的名字 you@example.com`。不设置会用默认值。不要用 GitHub 的 `noreply` 邮箱，SEC 会返回 403。
4. Actions 页手动运行一次 `publish-dashboard`，之后每个工作日自动更新。网址是 `https://<用户名>.github.io/<仓库名>/`。

注意：Pages 在免费账号下要求仓库公开；私有仓库需要付费计划。看板是纯静态页面，没有后端。
